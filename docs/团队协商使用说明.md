# 团队方案使用说明

> Token 预算与用量估算功能已下线，待重新设计后再开放。设计器不再输出调用次数、Token 区间、预算档位，也不再提供 `/unlimited`。

## 团队如何建立

需求整理完成后输入“继续”，设计器按已确认的需求给出团队方案。规则如下：

- 每项需求都要由某个角色负责；整体目标（goal）由整个团队承担，无需分派给单个角色。
- 每个角色只列出自己真正负责的需求。两个角色的职责依据和类型完全相同，会被判为冗余并要求合并。
- 必须有交付角色（delivery）。只有需求中包含验收条目，或明确要求审阅、修订、校对时，才必须有检查角色（review）；否则质量由蓝图中的确定性验收保证。
- 遵循奥卡姆剃刀：覆盖全部需求的前提下角色越少越好，不设纯协调、汇总或转交角色（运行时已负责串行调度）。
- 通常只给一个方案；确有不同执行策略时可提供 2–3 个，差异写在“取舍”中。

## 查看、切换与确认

```text
继续              获取团队方案
/team             查看每个方案的交付成果、角色分工和取舍
/select standard  切换到 ID 为 standard 的方案（切换后需重新确认）
确认              确认当前需求与所选方案
/plan             生成项目蓝图
```

确认同时接受当前需求和所选团队。之后再修改需求或切换方案，都需要重新确认。

## 设计版本

需求澄清期间不计设计版本。首次整理完整需求时为设计第 1 版；随后补齐首个团队方案且需求未改变，仍属于该版。之后需求内容、团队方案或所选方案发生变化才递增。重试、确认、查看记录、改写摘要不增加版本。

## 旧会话兼容

下线前保存的会话仍可打开、确认和规划：其中的预算字段会被保留但不再显示或校验，只凭预算表述产生的偏好类需求也无需分派给角色。停在原“用量估算”步骤的会话恢复后，直接进入“输入规范”步骤。

生成项目的 `team_plan.json` 保存所选团队、需求修订号和角色到 Agent 的映射，不再包含预算字段。
