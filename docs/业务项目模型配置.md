# 业务项目模型配置

适用于 Astra 内置的配置型 LLM Agent。确定性 Agent 不需要模型；手写 Agent 或 Qwen SDK Agent 仍可使用自己的配置机制。

## 项目结构

新生成的业务项目包含：

```text
my_project/
├── project.yaml
└── configs/
    ├── model.json
    └── workflow.yaml
```

在 `project.yaml` 中声明项目内相对路径：

```yaml
model_config: configs/model.json
```

引擎在 `engine.load()` 时读取并校验文件，不请求模型。路径必须位于项目内，文件必须存在。模型参数成为本次加载的项目配置快照；修改文件后重新 `engine.load()`，或重新执行 CLI 命令。`inspect()` 的 `model_config` 字段可查看加载的配置，不含密钥值。

## 留白后自行配置

```json
{
  "base_url": "",
  "model": "",
  "api_key_env": "ASTRA_RUNTIME_API_KEY",
  "timeout": 300,
  "max_output_tokens": 8192,
  "token_parameter": "max_tokens",
  "stream": true,
  "response_format": "text",
  "reasoning_effort": "auto"
}
```

填写 API 基础地址 `base_url` 和服务商模型 ID。例如 `https://api.openai.com/v1` 或 `http://localhost:11434/v1`，Astra 自动追加 `/chat/completions`；允许末尾斜杠，保留服务自定义路径前缀。不要填写完整聊天接口地址。参数必须符合服务支持范围；`text` 表示不发送格式参数，Astra 仍校验返回的 JSON。`reasoning_effort: auto` 表示不发送思考参数。

本次为不兼容升级：`endpoint` 字段与 `ASTRA_DESIGNER_ENDPOINT`、`ASTRA_RUNTIME_ENDPOINT` 环境变量已移除，遇到会报错，不自动转换。请把配置键改为 `base_url`，删除地址末尾的 `/chat/completions`，环境变量改用 `ASTRA_DESIGNER_BASE_URL` 或 `ASTRA_RUNTIME_BASE_URL`，并清除旧变量。

允许 base_url 和 model 留白，项目仍可加载、检查、收集输入、运行确定性节点；运行到需要模型的节点时会明确报错，保留运行状态，不会自动回退到设计器模型。填写后重新启动运行器，可恢复失败运行。

`api_key_env` 填环境变量名，不能填密钥值。配置文件不允许 `api_key` 字段。需要认证时，在运行项目的环境中提供该变量；免认证本地服务可以不设置。

## 设计时选择

需求对话和旧版蓝图对话在 `/generate` 时询问：

- **1，默认：留白稍后配置。** 生成上述配置模板。
- **2：复制设计器当前模型配置。** 复制地址、模型名、超时、输出上限等参数，保存独立快照；以后修改设计器配置不会改变项目。

复制模式将 `api_key_env` 设置为 `ASTRA_DESIGNER_API_KEY`，不会把隐藏输入的密钥写入项目，也不会在试运行时自动注入该密钥。运行前设置该环境变量，或把 `api_key_env` 改成项目专用的密钥变量名。

独立生成命令默认留白，也可指定：

```powershell
# 复制设计器配置，可选 --designer-config 指定其他设计器配置文件
uv run astra-designer generate blueprint.yaml --output workspace/my_project --use-designer-model

# 复制准备好的项目模型配置
uv run astra-designer generate blueprint.yaml --output workspace/my_project --model-config my-model.json
```

两个选项互斥；命令不会为复制配置请求密钥或调用模型。Python API 对应 `generate_project(..., model_config=配置字典)`。

## 运行时优先级

1. 设置了 `ASTRA_RUNTIME_BASE_URL` 或 `ASTRA_RUNTIME_MODEL`：必须同时提供两者，使用运行时环境配置及 `ASTRA_RUNTIME_API_KEY`。未提供的其他参数采用运行时默认值，不从项目配置混合补齐。
2. 未指定运行时地址和模型，但项目声明 `model_config`：使用项目文件和其中 `api_key_env` 指定的密钥。
3. 旧项目未声明 `model_config`：保持原有设计器工作区配置回退行为。旧版设计器试运行也保持原有传递规则。

仅设置 `ASTRA_RUNTIME_STREAM` 等单个调优变量不会覆盖项目配置。项目模式下只单独读取 `api_key_env` 指定的密钥环境变量。

新项目的设计器试运行遵循相同优先级，不会用设计器当前模型覆盖项目选择。

## 后续修改与试运行

### 响应大小保护

设计器的 `.astra-designer/model.json` 和业务项目的 `configs/model.json` 都支持以下可选字段（省略时使用相同默认值）：

```json
{
  "max_response_bytes": 256000000,
  "max_content_bytes": 16000000
}
```

这两个字段应加入现有模型配置，不替换地址和模型等其他字段。单位是字节，1 MB = 1,000,000 字节，必须是正整数。

- `max_response_bytes`：每次请求的响应传输总量，默认 256 MB。流式响应包含 SSE 数据、协议字段、思考内容和心跳；非流式包含整个响应 JSON，不含 HTTP 头。
- `max_content_bytes`：最终回答正文的 UTF-8 字节数，默认 16 MB。流式接收逐块累计正文；思考字段不计入正文，但仍受传输总量限制。

两项限制独立检查，先触及任意上限就终止该次响应，不将截断内容作为有效结果。设计器会保存失败诊断，错误提示包含触发的字段、已接收字节数和上限，可调整后重试。

设计器环境变量为 `ASTRA_DESIGNER_MAX_RESPONSE_BYTES` 和 `ASTRA_DESIGNER_MAX_CONTENT_BYTES`；完整运行时环境覆盖配置对应 `ASTRA_RUNTIME_MAX_RESPONSE_BYTES` 和 `ASTRA_RUNTIME_MAX_CONTENT_BYTES`。项目复制设计器配置时一并复制这两个参数。

256 MB 是接收上限，不预先分配相应内存；非流式解析和流式数据拼接仍可能产生额外内存开销，因此它不是进程内存上限。大小保护与 `timeout`、输出 Token 上限及业务预算分别生效。

生成的 `configs/model.json` 是允许修改的配置文件，不会因修改它而触发“生成文件已变化”。试运行会校验其结构，并在报告中保存 `model_config_sha256`（项目配置的规范化哈希，不包含密钥，也不代表环境覆盖后的最终参数）。工作流、Agent 和其他生成文件仍执行原有一致性检查。

配置文件已纳入生成项目的包资源。迁移项目时携带文件，在目标环境中重新提供密钥即可，无需保留设计器目录。

已有项目可手动添加配置文件和 `model_config` 声明；此前生成的项目如需使用新的可编辑模型配置试运行规则，应使用新生成器重新生成到新目录。
