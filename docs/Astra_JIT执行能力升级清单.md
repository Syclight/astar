# Astra 执行能力升级清单：借鉴 JIT-Agent

记录日期：2026-09-12

状态：未来升级参考，尚未按本清单实施。复选框表示对应升级项是否完成，不代表当前框架完全没有相关基础能力。

## 背景与方向

参考论文《Scaling Harness Intelligence via Just-in-Time Harness Evolution》（JIT-Agent，arXiv:2608.25593v1）。本文依据讨论时阅读的 v1 整理；后续复核请区分论文版本。

- 论文版本：https://arxiv.org/abs/2608.25593v1
- 官方实现：https://github.com/bingreeky/JIT

Astra 保留需求澄清、版本确认、业务项目生成、Stage → Agent → Tool 结构以及运行恢复机制，逐步加入适合不同任务的执行策略。优先提升实际执行和验证能力，再探索动态生成执行组件与专门训练。

目标结构：

```text
需求澄清与确认
      ↓
业务项目：Stage → Agent → Tool
      ↓
Agent 执行策略：记忆、规划、行动、工具选择
      ↓
运行记录与验收 → 比较策略效果 → 复用有效策略
```

## 建议实施顺序

### 第一阶段：完成最小执行闭环

完成四项 P0，再实现一个最小的“计划执行”策略。策略接口先满足该案例，随后在第二阶段完善。

验收目标：

> 用户提出资料处理任务后，Astra 能自行调用已有工具、完成多个步骤、验证产物，并在失败后正确恢复；整个过程可追踪、可评测。

### 第二阶段：实现策略选择

完成 P1，建立少量经过验证的策略，让 Designer 根据任务选择。保留现有确定性 Agent 和结构化转换 Agent，工具型 Agent 与它们共存。

验收目标：同类业务项目可以切换策略，在相同模型、输入和工具条件下比较效果。

### 第三阶段：扩展复杂任务与经验复用

按业务需要推进 P2。并行与动态委派需要先明确状态隔离、合并和恢复语义；经验库与优化闭环需要先具备可信的质量评价。

验收目标：复杂任务能受控执行，策略升级有对照结果且可回退。

### 第四阶段：探索生成与训练

在基础能力稳定、评测与数据积累充分后评估 P3。专门训练、动态生成执行代码和大规模多 Agent 并行不作为前期落地的前提。

验收目标：新增复杂度带来的收益可以通过实验验证，而不是仅凭生成方案或演示判断。
