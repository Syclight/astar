# 执行框架适配契约

框架选择属于技术配置，与业务需求确认分开。设计器默认按已登记能力匹配框架，也允许用户显式指定。模型服务与 Agent 框架是不同配置：使用 Ollama 或 Qwen 模型不要求使用 Qwen Agent。

## 查看支持情况

```powershell
python -m astra_designer frameworks
python -m astra_designer frameworks --show astra.configured@1
```

| 框架 ID | 当前生成支持 |
|---|---|
| `astra.native@1` | 可生成：复用现有确定性 Agent |
| `astra.configured@1` | 可生成：配置型 LLM Agent，校验 JSON 输入输出 |
| `qwen.agent@1` | 只有既有运行时适配；尚无 Designer 生成适配器 |
| `openai.agent@1` | 预留，尚未实现 |

列表说明能力、限制、配置要求、依赖安装情况及数据约定。查看列表不导入 Qwen SDK、不访问模型，也不会安装依赖。Qwen 的依赖已安装也不代表其生成适配器已实现。

## 新手交互

在需求探索对话中使用：

```text
/frameworks
/execution
/framework auto
```

`auto` 按任务能力选择当前已实现的生成器：确定性步骤用 native，结构化模型处理用 configured。此选择不依据模型臆测的价格或质量排名。

显式指定模型 Agent 的默认框架：

```text
/framework astra.configured@1
```

指定某一个 Agent（名称以蓝图实际 ID 为准）：

```text
/framework astra.configured@1 classifier
```

单 Agent 覆盖优先于默认值。设置某个 Agent 为 `auto` 可恢复该 Agent 的自动选择。未知 Agent 会在重新规划时被检查出来。

框架变更保留需求与团队确认，但清除当前规划，需重新 `/plan`。规划通过后显示实际框架及选择理由，然后使用 `/generate`。显式选择不支持的框架会直接报错，不会自动换成另一个框架。

默认框架仅应用于模型 Agent；确定性步骤继续使用 native。对确定性 Agent 显式覆盖为不兼容框架时会拒绝生成。

## 蓝图配置

```yaml
execution:
  default_framework: auto
  agents:
    reader: astra.native@1
    classifier: astra.configured@1
```

可直接编辑独立蓝图，先 `validate` 再生成。Agent ID 必须实际存在，且所选框架必须满足能力要求。

对于尚未锁定的蓝图，也可以设置生成时的模型 Agent 默认框架：

```powershell
python -m astra_designer generate blueprint.yaml --output workspace/new/my_project --framework astra.configured@1
```

`--framework` 不覆盖蓝图中的单 Agent 显式选择。模型接口、模型名称与密钥继续使用已有运行配置，不随框架选择自动修改。

## 固定选择与运行

规划和生成时保存 `frameworks.lock.json`，包含每个 Agent 的具体框架 ID、契约摘要及契约内容。生成项目内的蓝图也将自动选择展开为具体的单 Agent 配置。

工作流写入确定的 Agent 类，Astra 运行时不需要框架推荐器，不会按环境重新选择框架。重新生成时若检测到锁定的契约或选择变化，会要求重新规划新版本。旧版没有 execution 配置的蓝图按自动模式兼容。

此锁固定框架契约与选择，并非完整 Python 依赖环境锁；升级运行时依赖仍需回归测试。

## 开发者结构

```text
astra_designer/
├── resources/frameworks.json     框架契约目录
└── frameworks/
    ├── registry.py               查询、兼容性检查、确定性选择
    └── adapters.py               将能力转换为具体工作流 Agent 配置
```

契约采用 JSON 数据文件；业务项目使用 YAML 配置。契约声明支持范围，Python 适配器实现生成。新增框架必须同时增加版本化契约、生成适配器和验证测试；仅编辑能力声明不会让第三方代码自动加载。

当前验证覆盖自动匹配、显式覆盖、能力不兼容、未实现框架拒绝、锁定后重新生成、契约变化拒绝、需求确认保留，以及生成项目实际离线运行。没有执行真实 Qwen 或 OpenAI SDK 测试，二者未被标为可自动生成。
