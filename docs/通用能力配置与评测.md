# 通用能力配置与评测

本文说明网络搜索、发送邮件、绘图、扫描件识别、人工审阅、定时运行这几项能力需要做的一次性配置，以及如何用真实模型评测整个设计与运行流程。

密钥、授权码一律放在环境变量里，不写进项目文件。定时运行的计划任务只能读到永久环境变量，所以在 Windows 上请用 `setx` 设置（设置后需重新打开终端）：

```powershell
setx ASTRA_SEARCH_PROVIDER bocha
setx ASTRA_SEARCH_KEY "你的 Key"
```

## 网络搜索（web.search@1）

团队可以按搜索词联网找资料，得到标题、网址和摘要，也可以读取排名靠前的网页全文。搜索服务任选一种：

| `ASTRA_SEARCH_PROVIDER` | 说明 | 还需设置 |
|---|---|---|
| `bocha` | 博查，中文结果好，国内可直接访问 | `ASTRA_SEARCH_KEY`（博查开放平台申请） |
| `brave` | Brave Search API | `ASTRA_SEARCH_KEY` |
| `tavily` | Tavily，面向 AI 的搜索 | `ASTRA_SEARCH_KEY` |
| `searxng` | 自己部署的 SearXNG，不需要 Key | `ASTRA_SEARCH_URL`，如 `http://localhost:8080`（需开启 JSON 输出） |

搜索词有三种来源：固定模板（可带本次输入，如“{topic} 最新进展”）、每次运行输入，或由上游模型先生成几条搜索词。

## 发送邮件（email.send@1）

邮件通过邮箱的 SMTP 服务发出。QQ 邮箱、163 邮箱、企业邮箱都需要先在网页端开启 SMTP 并获取“授权码”。

| 环境变量 | 说明 | 例子 |
|---|---|---|
| `ASTRA_SMTP_HOST` | 发信服务器 | `smtp.qq.com`、`smtp.163.com`、`smtp.exmail.qq.com` |
| `ASTRA_SMTP_PORT` | 端口，默认 465 | `465`（SSL）或 `587`（STARTTLS） |
| `ASTRA_SMTP_USER` | 登录账号 | `me@qq.com` |
| `ASTRA_SMTP_PASSWORD` | 授权码（不是登录密码） | |
| `ASTRA_SMTP_FROM` | 发件人，默认同账号 | |
| `ASTRA_SMTP_SECURITY` | `ssl`、`starttls` 或 `none`，一般不用设 | |

邮件正文取上游写好的文本，附件可以带上本次运行写出的文件，收件人可以固定，也可以每次输入。发送邮件属于对外动作，不能放在返工循环里。

## 绘图与改图（image.generate@1、image.edit@1）

团队可以调用你自己部署的绘图模型（如 Qwen-Image-2.1）生成海报、插图、商品图、Logo，或按指令修改图片。服务需要提供 OpenAI 兼容的图片接口：生成用 `/v1/images/generations`，改图用 `/v1/images/edits`。用 vLLM-Omni 部署 Qwen-Image-2.1 时，启动命令为：

```bash
vllm serve Qwen/Qwen-Image-2.1 --omni --port 8091
```

需要透明背景时，启动时再加 `--color-format RGBA`。SGLang-Diffusion 等其他框架只要提供同样的接口也可以使用，启动方式以各自的文档为准。

| 环境变量 | 说明 | 默认 |
|---|---|---|
| `ASTRA_IMAGE_URL` | 接口地址，填到 `/v1` 为止；只写主机和端口时自动补 `/v1` | 必填 |
| `ASTRA_IMAGE_MODEL` | 请求中的 model，按服务启动时的模型名填写 | 不发送 |
| `ASTRA_IMAGE_KEY` | 服务要求密钥时填写，以 `Bearer` 方式发送 | 不发送 |
| `ASTRA_IMAGE_TIMEOUT` | 单次请求的最长等待秒数；2K 图步数多时会比较慢 | 600 |
| `ASTRA_IMAGE_CONCURRENCY` | 同时发出的请求数；一张显卡建议保持 1 | 1 |
| `ASTRA_IMAGE_EXTRA` | 附加到每个请求的参数（JSON），如 `{"num_inference_steps": 30}`；值写 `null` 可去掉服务不认识的字段，如 `{"response_format": null}` | 无 |
| `ASTRA_IMAGE_MAX_REFERENCES` | 合成时一次最多参考几张图片（vLLM-Omni 为 4） | 4 |
| `ASTRA_IMAGE_EDIT_FIELD` | 改图时图片的表单字段名；vLLM-Omni 用 `image`（多张时重复），OpenAI 官方接口用 `image[]` | image |
| `ASTRA_IMAGE_USE_PROXY` | 设为 `1` 时通过系统代理访问绘图服务；默认直连，适合局域网内的服务 | 直连 |

```powershell
setx ASTRA_IMAGE_URL http://192.168.1.20:8091/v1
setx ASTRA_IMAGE_MODEL Qwen/Qwen-Image-2.1
```

先用下面几行确认服务可用（重新打开终端后执行），成功会在当前目录得到 test.png：

```powershell
$body = @{ model = $env:ASTRA_IMAGE_MODEL; prompt = "a red apple on a white table, studio light"; n = 1; size = "1024x1024"; response_format = "b64_json" } | ConvertTo-Json
$r = Invoke-RestMethod -Uri "$env:ASTRA_IMAGE_URL/images/generations" -Method Post -ContentType "application/json" -Body $body -TimeoutSec 600
[IO.File]::WriteAllBytes("$PWD\test.png", [Convert]::FromBase64String($r.data[0].b64_json))
```

使用要点：

- 每次请求发送 `prompt`、`n`、`response_format=b64_json`；`size` 在指定了画面比例时发送（改图不指定比例时保持原图尺寸）；设置了才发送 `model`、`negative_prompt`、`seed`。服务返回 `b64_json` 或图片链接都可以，链接只接受 http/https，密钥只发给绘图服务本身。
- 服务返回的张数少于要求的张数时，会逐张补齐。设置了固定种子时，每张图单独请求（种子依次加 1），这样每张图都能按记录的种子重新生成。
- 设置 `negative_prompt` 会打开模型的引导（CFG），生成时间大约翻倍，没有特别需要可以不设。
- 画面比例从 1:1、4:3、3:4、3:2、2:3、16:9、9:16 中选，程序换成 Qwen-Image-2.1 推荐的 2K 尺寸（如 16:9 为 2752×1536）；设 `resolution=1k` 时每边减半，出草图更快。
- 这个模型用详细的英文提示词效果最好，所以设计器一般会在出图前安排一个模型步骤，把中文需求写成英文提示词；画面中要出现的文字会用引号原样写进提示词。
- 透明背景（Logo、贴纸）会按模型要求的写法包装提示词；服务以 RGBA 模式启动并返回带透明通道的 PNG 时原样保存。
- 图片保存在本次运行目录的 `images/<步骤名>/` 下，同一目录的 `images.json` 记录每张图的提示词、尺寸和种子。
- 邮件附件合计不超过 20 MB，一张 2K 图片就有几 MB，发图时少选几张，或用 `resolution=1k`。
- 审阅图片时，命令行会列出图片路径，并在 Windows 和 macOS 上用系统看图程序打开（设 `ASTRA_REVIEW_OPEN=0` 可关闭自动打开）。写下修改意见后，团队会重写提示词并重画。
- 没有配置地址、服务连不上，或服务前的网关返回 502/503/504 时，运行会在出图这一步暂停，前面的步骤不会白做。生成过程中服务断开（常见原因是显存不足）或超时则报错，不会自动重发，以免显卡重复生成。启动服务后用 `uv run astra resume <project.yaml> <运行ID>` 继续。
- 单个步骤一次运行默认最多生成 20 张图，可在蓝图中用 `max_images` 调整，避免误操作长时间占用显卡。

## 扫描件与图片识别（document.read@1）

扫描版 PDF 和图片（png、jpg 等）需要先把文字识别出来。安装两个组件即可，模型在本机运行，不需要联网：

```powershell
uv pip install rapidocr_onnxruntime pypdfium2
```

装好后，读取文档时遇到没有文字层的 PDF 页面或图片会自动识别。普通 PDF 页面仍按原文字读取，只有扫描页才识别。没有安装时，会提示需要安装什么。

## 运行中的人工审阅（human.review@1）

团队可以在任意一步停下来，把成果交给人看，常见用法是写完稿先让人审。运行到审阅步骤时，命令行会显示内容摘要和完整内容的文件位置：

- 输入“通过”：继续后面的步骤。
- 直接输入修改意见：意见交给后续步骤，通常配合条件跳转回到写作步骤返工，改完后会再次请你审阅。
- 输入 `/quit`：保存进度，稍后再审。

稍后继续审阅：

```powershell
uv run astra resume <project.yaml> <运行ID>                    # 交互审阅
uv run astra resume <project.yaml> <运行ID> --approve          # 直接通过
uv run astra resume <project.yaml> <运行ID> --notes "开头太长"   # 不通过，附意见
```

## 定时运行（astra schedule）

定时运行交给操作系统的计划任务：Windows 用“任务计划程序”，Linux 和 macOS 用 cron。团队本身不需要定时步骤。

```powershell
# 每周一、周五 8:30，用固定的任务资料运行周报项目
uv run astra schedule business/weekly_report --weekly MON,FRI --at 08:30 --input task.json

# 每天 7:00
uv run astra schedule business/weekly_report --daily 07:00 --input task.json

# 删除
uv run astra schedule business/weekly_report --remove
```

- 运行脚本和日志保存在项目的 `schedules/` 目录。任务资料会复制一份到这里，之后修改原文件不影响计划任务。
- 定时运行会自动确认本单资料。清理文件的清单确认和人工审阅仍然会停下来等人处理，不会被自动跳过。
- 在 Linux 和 macOS 上，命令会给出一行 cron 配置，用 `crontab -e` 加入即可。

## 用真实模型评测（astra-designer evaluate）

评测集包含 13 个典型业务任务：工资计算、销售汇总、周报、合同审阅、会议待办、反馈分类、带返工的文章、文档翻译、文件清理、连载小说、联网调研、活动海报、商品图换白底。每个任务从“已确认的需求”开始，依次经过规划蓝图（含修复）、生成项目、用样例资料运行、蓝图验收、成果检查（如工资合计是否精确、审阅意见是否指出了关键条款）。

```powershell
uv run astra-designer evaluate --show-cases                          # 查看用例
uv run astra-designer evaluate                                       # 全部用例，设计和运行都用设计器模型
uv run astra-designer evaluate --cases payroll,weekly_report         # 只跑部分用例
uv run astra-designer evaluate --project-config configs\run_model.json  # 运行项目改用另一个模型
```

- 报告保存在 `workspace/evaluations/<时间>/report.md`，同目录下保留每个用例的设计会话、生成项目和运行记录，便于排查。
- 评分：设计 40、生成 10、运行完成 20、蓝图验收 15、成果检查 15，蓝图验收和全部成果检查都通过才记为通过。报告同时给出设计成功率、验收通过率，以及规划的平均模型调用次数和用时。
- 评测的是规划、生成与运行。需求访谈的质量不在评测范围内，需求由用例直接给出。
- 联网调研用例需要先配置搜索服务，两个绘图用例需要先配置 `ASTRA_IMAGE_URL`，否则自动跳过。
- 一次完整评测会调用模型几十次，用时从十几分钟到一小时不等，取决于模型速度。建议先用 `--cases` 跑两三个用例试试。
- 换模型或修改提示词后重新跑一遍，对比两份报告，就能看出改动是变好还是变坏。
