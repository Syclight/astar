# 可执行能力包

内置 capability、已有的 `.capability.json` 配方与能力包共用设计器目录和输入输出契约。配方仍是内置能力的参数组合；能力包可提供新的 Python 执行实现，不需要修改 Astra 的能力白名单。

## 使用

```powershell
uv run astra-designer packs check examples/capability-packs/web_security
uv run astra-designer packs install examples/capability-packs/web_security
uv run astra-designer packs list
uv run astra-designer capabilities --show web_security.headers@1
uv run astra-designer generate examples/blueprints/web_security/blueprint.yaml --output workspace/web_security_demo
uv run astra run workspace/web_security_demo
```

包安装到当前目录下的 `workspace/capability-packs`。可用 `ASTRA_CAPABILITY_PACK_HOME` 指定固定绝对目录，供不同工作目录共用。安装相同内容的同版本可重复执行；同版本不同内容会拒绝安装。安装新版本会激活该版本，旧版仍保留。要重新激活旧版，可安装同内容旧包。

卸载使用包名（不是路径或 capability ID）：

```powershell
uv run astra-designer packs uninstall web_security
```

这会取消该包的目录登记并删除全部已安装版本，之后新设计不再发现该包。源码目录、已生成团队中的锁定副本和运行结果保持不变，已有团队仍可运行；重新生成使用该能力的蓝图前需要重新安装对应版本。不执行包内卸载脚本，也不卸载系统级依赖。若文件被占用而清理失败，命令会明确显示残留位置，此时该包已经取消登记。

`packs check` 检查清单、文件路径、Python 语法、Schema 和声明依赖，不导入实现代码、不进行网络扫描。`ready` 表示声明依赖齐备，不代表专业功能经过真实环境验证；缺依赖为 `needs_configuration`，check 退出码为 1。列出缺失环境变量时只显示名称，不显示值。Astra 不自动安装外部依赖，也不把密钥写入生成项目。

设计器能看到包的用途、端口、参数、指南和配置状态。生成项目会复制用到的完整包到 `capability_packs/包名/版本`，写入 `capability-packs.lock.json`，并将哈希绑定在工作流节点上。已有项目不依赖全局安装目录；升级或改变全局包不会改变旧项目的执行代码。锁定不覆盖外部扫描器、系统库或远程服务的版本。

带任务资料接收阶段的团队会在运行前检查全部包依赖；每个包节点执行时也再次检查。缺依赖会保存并暂停为 `waiting_dependencies`，配置完成后可用现有 `astra resume` 继续。包文件哈希不符会报错，不执行修改过的代码。

## 编写

完整示例在 `examples/capability-packs/web_security/`。版本 1 使用 UTF-8 文本文件：

```text
manifest.json        # 元数据、输入输出、参数 Schema、依赖、权限
implementation.py    # 执行入口
README.md            # 使用与覆盖范围
```

manifest 的 `files` 显式列出要分发的文件（不含 manifest 自身）；路径不能越界。包名由小写字母、数字和下划线组成。能力 ID 为 `包名.能力@主版本`；Schema 标识必须以 `包名_` 开头，不得覆盖内置 Schema；Schema 必须自包含。`runtime: astra-pack@1` 声明执行接口版本，不支持的接口版本会被拒绝。

每个能力声明 `inputs`、`outputs`、`parameters`，以及 `entry: implementation.py:execute`。不支持通过清单动态执行 shell 安装脚本。可选 dependencies 按能力声明：

```json
{"environment": ["SERVICE_URL", "SERVICE_TOKEN"], "executables": ["docker"], "python_modules": ["requests"]}
```

入口函数：

```python
def execute(values, parameters, context):
    # values 为已验证的输入端口值；parameters 为已验证的能力参数。
    # context 包含 package_dir、output_dir、run_id。
    return {"result": {"status": "completed"}}
```

返回值必须恰好匹配 outputs 端口，且逐个通过 Schema 校验。运行框架负责输入输出验证、工作流接线和运行记录；包负责外部工具调用、超时、结果解析与业务范围限制。实现可通过 context.package_dir 读取声明的资源；当前加载入口为独立模块，不提供相对 Python 包导入协议。

permissions 可声明 network/process/filesystem，用于审阅和展示。**能力包是受信任的 Python 扩展，拥有当前 Astra 进程权限；声明不是沙箱。**安装、目录发现、自检不导入代码；工作流执行时才导入。用户应审阅并只安装可信来源的包。当前版本只支持本地目录安装，没有远程市场、签名或自动更新机制。

## Web 安全示例的边界

示例能力真实执行单 URL 请求，检查响应安全头，返回结构化观察和 Markdown 报告；不跟随重定向，不爬取、不尝试认证绕过、不执行漏洞利用。连接失败是执行错误；响应中发现配置问题不等于执行失败。

它不能替代原 `web_pentest` 团队要求的完整渗透测试引擎。要增加 ZAP/Nuclei 等执行器，在专业包中增加适配实现、依赖和证据 Schema，完成受控环境测试后再接入团队；不要用安全头检查偷偷替换完整渗透测试节点。
